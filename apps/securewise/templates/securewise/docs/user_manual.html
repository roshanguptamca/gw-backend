What SecureWise Does

SecureWise checks software projects for security issues before and after release. It can review source code, dependencies, secrets, infrastructure files, container images, API definitions, and running web applications when a safe test URL is provided.

Find risks early Identify risky code patterns, vulnerable packages, leaked secrets, and unsafe configuration before release.
Use ready-made policies Pick a default policy such as OWASP Web Baseline or copy it and adjust rules for your team.
Create shareable reports Generate HTML, PDF, and JSON report outputs for audits, teams, or CI/CD pipelines.

Before You Start

  • You need a SecureWise account and access to an organization.
  • You need permission to add projects, repositories, and scans.
  • For a Git repository, have the repository URL ready.
  • For a private Git repository, ask an administrator to connect the Git provider first.
  • For a local repository, know the folder path on the machine where the backend runs.
  • Only scan systems and repositories you are authorized to test.
Dynamic web scans send test traffic to a running application. Use a staging or test environment unless your team has approved production scanning.

Organization Setup

SecureWise keeps projects, repositories, scan policies, findings, and reports inside an organization. Before scanning, make sure you are working in the correct organization so the right team can see the results.

Open Organizations

Use Organizations in the SecureWise menu to view the organizations where your account is a member.

Create or choose the organization

If your company or team already exists, select it. If you have permission, create a new organization for the team that owns the repositories you want to scan.

Invite the right people

Add owners, administrators, security reviewers, developers, and auditors based on who should manage repositories, start scans, or only review reports.

Confirm permissions

If you cannot add a project, repository, scan policy, or scan, ask an organization owner or administrator to update your role.

For most users, the organization is selected once and then reused. After that, your normal workflow is Projects, Repositories, Scan Policies, Scans, Findings, and Reports.

Run Your First Scan

Sign in

Open the SecureWise portal and sign in with your account.

Choose the organization

Confirm you are in the organization that owns the application you want to scan. This controls who can access the scan results.

Create or choose a project

Go to Projects. Create a project for the application you want to scan, or open an existing project.

Add the repository

Go to Repositories, choose Add Repository, enter the repository details, then use Validate before saving.

Select a scan policy

Go to Scan Policies. Use a default template, make it the organization default, or copy it if your team needs a custom version.

Create the scan

Go to Scans, choose the project and repository, select the scan type, then create the scan.

Start and monitor

Start the scan and watch the status. When it finishes, open the scan to review findings and report outputs.

Scan a Local Repository

A local repository scan lets you scan code from a folder path instead of a Git URL. This is useful when the code is on your machine, not pushed to a remote provider, or not ready to share.

Open Repositories

Choose Add Repository.

Select local access

Set Access Type to Local path on this machine.

Enter the folder path

Enter a path such as /Users/you/projects/my-app or another readable project folder.

Validate and save

SecureWise checks that the path exists, is readable, is not empty, and looks like a supported project.

Run the scan

Go to Scans and select the saved local repository from the repository list.

In local development, the backend usually runs on your computer, so the path is your computer's path. In Docker or production, the path must exist inside the backend container or server.

Use Scan Policies

A scan policy controls what SecureWise checks and when a scan should be considered failed. Policies help teams run consistent scans.

Use as default Makes the selected template the normal policy for new scans in the organization.
Copy template Creates a new policy from a template so your team can adjust thresholds without changing the original template.
Latest market scan Uses the latest bundled SecureWise template set for broad coverage.

If you are unsure, start with OWASP Web Baseline for web applications and APIs.

Supported Scan Types

SAST Reviews source code for risky patterns.
SCA Checks third-party dependencies for known vulnerabilities.
Secrets Looks for accidentally committed passwords, keys, or tokens.
IaC Reviews infrastructure files such as Terraform, Kubernetes, and cloud configuration.
API Checks API definitions and routes where available.
DAST Tests a running web application from the outside using an approved target URL.
Container Checks container images and Docker-related files.
Full scan Runs the broadest available set of checks for the repository and target information provided.

Understand Results

Scan results are shown as findings. Each finding explains what was detected, where it was found, how serious it is, and what action the team should take.

Severity usually appears as Critical High Medium Low

  • Critical: Treat as urgent. These can represent serious exposure.
  • High: Fix soon, especially before release.
  • Medium: Review and plan remediation.
  • Low: Track or fix as part of normal cleanup.

Finding actions

  • Open: Needs review or action.
  • Accepted risk: The team understands the issue and accepts it for now.
  • False positive: The finding does not apply after review.
  • Fixed: The issue has been corrected and should be verified by a new scan.
Use AI suggestions as a starting point. A project owner or developer should still review the fix before applying it.

Download Reports

After a scan completes, open Reports or the scan details page to generate and download outputs.

  • HTML report: Easy to read in a browser and share with stakeholders.
  • PDF report: Useful for audits, approvals, and offline sharing.
  • JSON report: Useful for automation and CI/CD systems.
Reports can include file paths, package names, code locations, and vulnerability details. Share them only with authorized people.

GitHub and Jenkins

SecureWise can be used from CI/CD pipelines so scans run during a release process. Your administrator or DevOps team can use the provided GitHub Actions and Jenkins examples to install dependencies, run scans, store reports, and fail builds when severity thresholds are exceeded.

  • Use the portal for day-to-day scan review and reporting.
  • Use GitHub Actions when scans should run automatically on pull requests or branches.
  • Use Jenkins when your organization already manages builds through Jenkins jobs.

For technical setup details, open the Developer Documentation.

Troubleshooting

The repository will not validate

Check that the URL or local path is correct, the repository is not empty, and the SecureWise backend has permission to read it.

The local path cannot be found

The path must exist on the machine or container running the backend. A path on your laptop will not work if the backend is running on a separate server unless that path is mounted there.

The scan finished with no findings

This can mean no supported issue was found, or the repository type has limited scanner coverage. Review scan logs and the selected scan type.

The DAST scan was skipped or failed

Confirm the target URL is reachable from the backend or scanner container and that your team has approved testing that application.

The scan failed because of severity threshold

Open the findings list, review Critical and High issues first, then fix, accept risk, or mark false positives based on your team's approval process.

I am not sure what to choose

Use the default scan policy, run a full scan for broad coverage, and ask a project owner or security reviewer to help triage the findings.

Short Glossary

  • Project: The application or service you want to protect.
  • Repository: The source code location for a project.
  • Scan: A SecureWise check run against a repository or target.
  • Finding: A security issue or warning found by a scan.
  • Policy: The rules and thresholds used during a scan.
  • Artifact: A generated file such as an HTML, PDF, or JSON report.

This manual intentionally avoids secrets, tokens, and sensitive environment values. Use it as a user guide for portal workflows.
