SecureWise Developer Documentation

Public, sanitized reference for SecureWise architecture, setup, scanning, APIs, CI/CD, and local repository usage.

Project Overview

SecureWise is the application security platform inside the GuideWisey Django backend. It provides organization-scoped projects, repositories, scan policies, scans, findings, reports, Git integrations, and audit logs. The scanner layer supports SAST, SCA, secrets, IaC, container, API, and DAST engines with real-tool execution where available and transparent fallback modes where not.

Control Plane
Organizations, memberships, projects, repositories, policies, scans, reports, findings, audit logs.
Scanner Layer
Semgrep, Trivy, Gitleaks, OWASP ZAP baseline, OpenAPI checks, and Python fallback scanners.
Reports
JSON, HTML, and PDF report generation with OWASP, CWE, severity, remediation, and quality-gate sections.
Developer Workflows
GitHub issue/PR creation, CI/CD examples, and local repository scanning via CLI.

Setup Steps

cd gw-backend
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver

Optional external tools improve scan fidelity:

pip install semgrep
brew install trivy gitleaks
docker pull ghcr.io/zaproxy/zaproxy:stable

Scan Workflow

  1. User creates or selects an organization, project, repository, and scan policy.
  2. A scan is created through /api/securewise/scans/.
  3. ScannerRunner clones the configured repository into a temporary directory.
  4. ScannerOrchestrator resolves engines from scan type and repository contents.
  5. Each engine writes a SecureWiseScanEngineResult with mode metadata: real tool, fallback, passive only, or skipped.
  6. Findings are normalized, deduplicated by fingerprint, persisted, and used for quality-gate evaluation.
  7. Reports can be generated as JSON, HTML, or PDF.

GitHub Actions Integration Guide

Use the local CLI in CI to scan the checked-out repository. The example writes both JSON and HTML reports and fails the job when the configured severity threshold is met.

name: SecureWise Scan
on: [push, pull_request]
jobs:
  securewise:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.11"
      - run: pip install -r requirements.txt
      - run: python manage.py migrate --noinput
      - run: python -m apps.securewise.cli scan --path . --output securewise-report --fail-on high
      - uses: actions/upload-artifact@v4
        with:
          name: securewise-report
          path: securewise-report/

Jenkins Integration Guide

pipeline {
  agent any
  stages {
    stage('SecureWise Scan') {
      steps {
        sh 'python3 -m venv .venv'
        sh '. .venv/bin/activate && pip install -r requirements.txt'
        sh '. .venv/bin/activate && python manage.py migrate --noinput'
        sh '. .venv/bin/activate && python -m apps.securewise.cli scan --path . --output securewise-report --fail-on high'
        archiveArtifacts artifacts: 'securewise-report/**', fingerprint: true
      }
    }
  }
}

Local Repository Scan Guide

Scan a path from the SecureWise UI

  1. Open Repositories and choose Add Repository.
  2. Set Access Type to Local path on this machine.
  3. Enter a readable path such as /Users/you/projects/my-app or another path visible to the backend process.
  4. Validate and save the repository.
  5. Open Scans, create a scan, and select the saved local repository from the repository dropdown.

In local development, the backend usually runs on your machine, so local paths are your local filesystem. In production, the path must exist inside the backend server/container.

Scan a path from the CLI

python -m apps.securewise.cli scan --path /path/to/repository
python -m apps.securewise.cli scan --path . --output securewise-report --fail-on high

The UI and CLI validate path existence, directory access, empty repositories, and recognizable project signatures. CLI scans write securewise-report.json and securewise-report.html.

Troubleshooting

SymptomLikely CauseAction
Scan is completed_partialNo real external scanner ran successfully.Install Semgrep, Trivy, Gitleaks, Docker, or ZAP depending on needed engines.
DAST is skippedNo target URL and runtime could not be safely started.Provide target_url or add Dockerfile/Compose/start command and health endpoint.
Container scan is skippedNo image configured or Docker/Trivy unavailable.Set docker_image or install Docker and Trivy.
Local CLI says unsupported projectNo supported language/framework or scannable files detected.Confirm the path points to the repository root and includes source/dependency/config files.
CI job fails on severityFindings met or exceeded --fail-on.Fix findings, adjust policy threshold, or explicitly accept risk in your governance process.
Security note: local and CI reports may contain file paths, finding descriptions, and code snippets. Treat report artifacts as internal security data.
